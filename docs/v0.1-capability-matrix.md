# v0.1 Capability Matrix

This document summarizes which MCP tools are expected to work on Snowstorm vs Snowstorm Lite
for the current v0.1 read-first scope.

## Capability Matrix

| Tool | Snowstorm | Snowstorm Lite | Notes |
|------|-----------|----------------|-------|
| `list_terminologies` | Yes | Yes | Server-level tool; returns routable terminologies. |
| `server_health` | Yes | Yes | Uses backend probe results and reachability checks. |
| `server_capabilities` | Yes | Yes | Includes summarized FHIR metadata when available. |
| `fhir_metadata` | Yes | Yes | Returns parsed summary; raw CapabilityStatement optional (`include_raw`). |
| `snomed_lookup` | Yes | Yes | FHIR `CodeSystem/$lookup`. |
| `snomed_validate_code` | Yes | Yes | FHIR `CodeSystem/$validate-code`; may fall back to lookup emulation when unsupported. |
| `snomed_subsumes` | Yes | Usually | FHIR `CodeSystem/$subsumes`; backend behavior varies by terminology content and FHIR implementation details. |
| `snowstorm_search_concepts` | Yes | No | Snowstorm native browser API only. |
| `snowstorm_get_concept_native` | Yes | No | Snowstorm native browser API only. |

## FHIR Operation Edge Cases (v0.1)

### `snomed_subsumes`

- Backend implementations may differ in accepted parameter combinations and error responses.
- Results depend on the loaded SNOMED edition/version and may vary if `version` is omitted on a multi-edition backend.
- Some backends may return `equivalent` instead of `subsumes` for specific concept pairs depending on interpretation of the pair/order.

### `snomed_validate_code`

- Some backends may not support `CodeSystem/$validate-code` directly.
- The MCP server can emulate validation via `CodeSystem/$lookup` as a compatibility fallback.

### `fhir_metadata`

- Use `include_raw=false` when you only need a compact summary and want to avoid large MCP payloads.

## v0.1 Scope Boundaries

### Included (current v0.1 direction)

- Read-first terminology access via MCP
- Multi-target routing with terminology-based selection
- FHIR read operations (`$lookup`, `$validate-code`, `$subsumes`)
- Snowstorm native read operations (search + concept detail)
- Capability probing and diagnostics

### Explicitly Out of Scope for v0.1 (v0.2+ Candidates)

- RF2/package upload/import workflows
- Authoring write operations (create/update concepts or reference set members)
- Admin/destructive operations (rollback/admin endpoints)
- Interactive OAuth/OIDC login flows and token refresh orchestration
